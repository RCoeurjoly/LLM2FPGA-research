# Constraint Programming and FPGA Accelerator Design (Survey)

* Scope and question

User question: *what does research say about constraint programming for accelerator design, and are there papers about it?*

This is a constraints-oriented view, with emphasis on:

- HLS scheduling / binding / mapping,
- resource assignment under timing/resource constraints,
- and SAT/CP use for router/placement sub-problems.

LLM-specific CP for FPGA inference is still sparse; most CP/ASP/SAT work is in
general accelerator synthesis and CAD optimization.

* Core findings

1. The strongest CP literature is in *front-end synthesis* rather than final
placement/routing:
   - CP is well-established for scheduling, binding, assignment and mapping.
   - Classic papers use JaCoP/CP-SAT and report strong optimality/near-optimality
     on HLS benchmarks.
2. Full placement/routing with pure CP is still rare as a production solution:
   - SAT and CSP formulations are used for routing legality / unrouteability checks
     or as accelerator subroutines, but whole P&R is usually too large for naive CP.
3. Modern accelerator toolflows still trend toward mixed approaches:
   - ILP / CP / MILP / heuristic + analytical models + physical feedback.
4. For LLM inference specifically, currently most papers are LLM-focused but do not use CP for core mapping (they use automation and RL/LLM-guided heuristics instead).

* Relevance to your LLM-on-FPGA stack (2026-06-10)

- High-confidence near-term CP payoff: use CP for
  - operator/block quantization choices,
  - tiling tuples,
  - memory hierarchy placement,
  - schedule/windowing constraints.
- Keep P&R out of the CP core loop initially; use CP to prune candidates before running yosys/nextpnr.
- For HLS-to-FPGA end-to-end reproducibility, use CP with hard constraints from board profile and keep a feedback loop that adds learned nogoods from failed builds.

* Note on direct LLM+CP papers

From this evidence pass, there are no widely cited, mature *LLM-specific* CP papers that become ready-to-run blueprints for FPGA inference pipelines. The strongest reusable signal comes from:
- LLM-DSE papers (e.g., 2605.05920 / 2606.11117), and
- long-standing CP/ASP/CSP work in HLS, mapping, and CAD.

In practice, the path is hybridization: CP as a front-end design-space optimizer + actual build/verification via open FPGA flow.
