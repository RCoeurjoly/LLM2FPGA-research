** 28 — Towards Autonomous Accelerator Design: FPGA Accelerator Generation with SECDA (arXiv:2606.11117) :: No-go

- Gate 0 (Feasibility Screening): **Fail**
  - Mandatory tooling in this paper is `SystemC`, `SECDA`, and `Vivado HLS 2019.2`.
  - Target workflow is explicit `Zynq-7000` FPGA with SECDA-specific constraints.
  - No public repository link is present in the survey record, and code availability is `none`.
- Gate 1 (Toy-Build Viability): **Not attempted** (blocked by Gate 0).
- Gate 2 / Gate 3: **Not applicable** (blocked by Gate 0).
- Decision: **No-go for this repo’s current open-source, YPCB-00338-1P1 path**.
- Failure mode: `toolchain-block`.
- Evidence used:
  - Local PDF text scan confirms `SECDA`, `SystemC`, and `Vivado HLS 2019.2` references and `Zynq-7000`.
  - No artifact/repo link in this registry row.

** 29 — Holistic Optimization Framework for FPGA Accelerators (arXiv:2501.09242) :: No-go

- Gate 0 (Feasibility Screening): **Fail**
  - The method is not LLM-specific and is a general HLS optimization framework.
  - Mandatory flow uses `AMD/Vitis HLS` and `OpenCL`; paper reports `OpenCL host code` and bitstream generation from Vitis toolchain.
  - Open-source repository exists (`github.com/UCLA-VAST/Prometheus`) but dependency openness remains mixed/proprietary around the execution stack.
- Gate 1 (Toy-Build Viability): **Not attempted** (blocked by Gate 0).
- Gate 2 / Gate 3: **Not applicable** (blocked by Gate 0).
- Decision: **No-go for direct LLM inference viability path in this repo**.
- Failure mode: `toolchain-block` and `scope-mismatch`.
- Evidence used:
  - arXiv abstract/intro confirms non-LLM scope + Vitis-focused generation flow.
  - `open` extraction includes contribution bullet: `end-to-end compilation ... Vitis-HLS... bitstreams`.
  - `References` section identifies the Prometheus GitHub repo but no direct OSS + Kintex/LLM bridge.

* Working notes
- Reproducibility-field vocabulary:
  - `Code availability`: `repo`, `artifact_only`, `private`, `promised`, `withdrawn`, `none`
  - `Dependency openness`: `open`, `mixed`, `proprietary`
- `Board dependency`: normalized board token used only for quick filtering
- `Board dependency` tokens are normalized by hand to keep filtering stable:
  - `board_agnostic`, `fpga_generic`, `zcu102`, `u280`, `kv260`, `zynq_7000`, `edge_fpga_unspecified`, `fpga_asic_prototype`, etc.
- `Parameter completeness`: `na`, `partial`, `complete`
- `Rerun actionability`: `yes`, `conditional`, `no`
- `Reproducibility signal`: `low`, `medium`, `high`
- `Artifact quality`: `low`, `medium`, `high`
- Prioritize papers that are both open and practical for open-source Kintex-480T workflows:
  - XtraMAC (ID 21)
  - MASE (ID 9)
  - Spatial acceleration (ID 12)
  - HLSTransform / HLS with MLIR-CIRCT (ID 11, 14) as method references
